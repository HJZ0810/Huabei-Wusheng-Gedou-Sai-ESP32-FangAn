# V1.0：建立完整的四驱无线控制工程

版本基线：[1b04fd7485a531d5d85fe769732636cfa675b90e](https://github.com/HJZ0810/Huabei-Wusheng-Gedou-Sai-ESP32-FangAn/commit/1b04fd7485a531d5d85fe769732636cfa675b90e) · 作者：HJZ · 许可证：[MIT](../../LICENSE)

**[完整历史工程](../../versions/v1.0/CombatBot_ESP32S3/)** · [原始 README](../../versions/v1.0/CombatBot_ESP32S3/README.md) · [V2.0 演进](V2.0.md) · [V3.0 演进](V3.0.md)

历史发布入口：[V1.0 Release](https://github.com/HJZ0810/Huabei-Wusheng-Gedou-Sai-ESP32-FangAn/releases/tag/v1.0)，源码附件为 `CombatBot_V1.0_Archive.zip`。本次恢复的是上述公开提交的原始快照，不新增历史硬件或编译验证。

V1.0 的价值是把电机、反馈、传感器、网页和参数管理组织成一套可阅读、可修改的 Arduino 工程。它提供连续驾驶与定点距离/转角两条操作路径，建立后续版本沿用的硬件模块和使用流程。这里保留完整源码及原始资料，同时补充源码能够支持的能力说明和限制，便于按版本理解演进。

本页以公开提交为准。历史文件内出现的 V1.1 注释修订号属于当时文件记录；本仓库用 V1.0 标识这一公开基线，不修改原始文件中的版本字段。

## 已实现的功能

| 领域 | V1.0 实现 | 对使用者的价值 |
|---|---|---|
| 无线接入 | 常驻 AP、可选 STA、mDNS、强制门户与内嵌网页 | 没有外部服务器也可接入车辆；可按场地选择直连或路由器 |
| 连续驾驶 | 摇杆归一化输入、速度百分比和差速混合 | 同一输入表达前进、后退和左右转向 |
| 定点直线 | 四轮平均 FG 行程、剩余距离驱动的梯形规划、航向修正 | 提供按厘米下发动作及完成反馈的基础 |
| 定点转向 | 左右轮行程主转、可用时增加 IMU 精修阶段 | 用轮速反馈和姿态反馈组合完成角度动作 |
| 电机反馈 | 四轮 PWM/DIR、GPIO FG 上升沿计数、带符号累计、转速和线速度 | 将轮速与距离带回控制计算和网页显示 |
| 姿态与冲击 | MPU6050 偏航积分、轮里程计互补融合、ADXL345 加速度及姿态信息 | 提供航向、倾角和冲击观察数据 |
| 环境与电源 | CD74HC4067 采集六路红外与电池；MCP23017 采集四路灰度、三路 E18 | 在有限 GPIO 上接入多路模拟和开关量 |
| 舵机 | 中位、举铲、放铲及脉宽端点配置 | 将铲子机构操作纳入控制页面 |
| 标定 | IMU 零偏、行程比例 K_odo、转向比例 K_turn | 为不同机械装配保留实测调整入口 |
| 参数管理 | JSON 配置读取、部分更新、NVS 保存及恢复默认 | 参数与代码分离，减少每次调参重新编译的需要 |
| 状态反馈 | WebSocket 遥测、动作完成事件与安全告警；REST 动作接口 | 便于网页展示进度，也为外部客户端保留入口 |
| 保护机制 | 连续模式心跳、急停锁定、低压限速/严重低压停机、堵转、可选边缘与 IR 保护 | 建立基本保护路径，为 V2 加固提供起点 |

“精准”是该操作模式的名称，不能由源码功能名称推断实车距离或角度误差。FG、打滑、安装方位、供电和标定结果共同决定实际效果。

## 模块职责与维护入口

所有 `.cpp/.h` 与主 `.ino` 同级，Arduino IDE 打开草图后可以在标签页逐模块阅读；PlatformIO 配置也扫描这一平铺目录。

| 模块 | 职责与阅读重点 |
|---|---|
| [CombatBot_ESP32S3.ino](../../versions/v1.0/CombatBot_ESP32S3/CombatBot_ESP32S3.ino) | 依次初始化配置、机器人、网络和网页，在主循环维护网络服务 |
| [cfg.h](../../versions/v1.0/CombatBot_ESP32S3/cfg.h) / [cfg.cpp](../../versions/v1.0/CombatBot_ESP32S3/cfg.cpp) | 参数结构、默认值、JSON/NVS、互斥量和配置快照 |
| [motor.cpp](../../versions/v1.0/CombatBot_ESP32S3/motor.cpp) | LEDC 跨 core 版本接口、电气方向、FG 中断计数、测速、舵机输出 |
| [pid.h](../../versions/v1.0/CombatBot_ESP32S3/pid.h) | PID 输出/积分限幅，以及按剩余距离计算的梯形速度规划 |
| [kinematics.cpp](../../versions/v1.0/CombatBot_ESP32S3/kinematics.cpp) | 脉冲、厘米和转角之间的换算及标定比例 |
| [imu.cpp](../../versions/v1.0/CombatBot_ESP32S3/imu.cpp) | 偏航融合、零偏采样、在线偏置更新、加速度与姿态 |
| [sensors.cpp](../../versions/v1.0/CombatBot_ESP32S3/sensors.cpp) | 模拟多路复用扫描、红外距离曲线、电池滤波、数字输入 |
| [safety.cpp](../../versions/v1.0/CombatBot_ESP32S3/safety.cpp) | 汇总心跳、电池、障碍、边缘与堵转结果，给出停机或速度比例 |
| [robot.cpp](../../versions/v1.0/CombatBot_ESP32S3/robot.cpp) | 指令队列、动作状态机、速度/航向运算、标定与遥测快照 |
| [wifi_mgr.cpp](../../versions/v1.0/CombatBot_ESP32S3/wifi_mgr.cpp) | AP/STA 状态、重连、DNS 和 mDNS |
| [web.cpp](../../versions/v1.0/CombatBot_ESP32S3/web.cpp) / [web_ui.h](../../versions/v1.0/CombatBot_ESP32S3/web_ui.h) | HTTP/WS、JSON 映射和可编辑的内嵌 HTML/CSS/JS |

任务代码把控制任务绑定 Core 0，以 5ms 为计划周期，传感器扫描降频到 20Hz。该安排体现了控制与页面处理分离的设计意图；ESP32 Wi-Fi、系统任务和共享总线仍参与调度，不能称 Core 0 被控制器独占，也不能由目标 200Hz 推断硬实时保证。

## 这一版的优势

- **功能链路完整。** 从用户输入到轮速反馈、动作进度和参数保存都有明确入口，适合作为整车联调起点。
- **结构直观。** 电机、运动学、姿态、传感器、保护、网页各自分文件，Arduino IDE 使用者可顺着调用关系阅读。
- **兼顾离线使用。** 网页随固件部署，AP 常驻，网络入口不依赖云服务。
- **考虑机械差异。** 行程/转向标定和左右比例修正可吸收一部分装配差异，而不是把理论轮径当成最终实测参数。
- **保留工程资料。** [原始文档索引](../../versions/v1.0/CombatBot_ESP32S3/docs/README.md) 包含设计、接线、验证和需求材料，方便追溯最初假设。

## 当时的边界与后续改进

以下来自历史源码阅读，目的是说明后来为何继续改进；不是宣称每一项已在实车上发生故障。

| V1.0 边界 | 后续版本的处理 |
|---|---|
| stop/estop 经过普通队列；投递失败可返回 false | V2 加入原子停止旁路与队列代次失效 |
| 没有按连接仲裁控制权；任意 WS 断开会投递 stop | V2 增加单一控制者；V3 进一步限制网页旁观者的自动停止 |
| FG 使用 GPIO 中断计数，电气取反与反馈符号耦合 | V2 优先 PCNT；V3 分离逻辑运动与电气极性 |
| 没有轮速降下来后再翻转方向线的等待 | V2 增加静默时间和低速双条件换向等待 |
| PID 积分限幅后仍继续累积，复位后的首拍会计算微分 | V2 增加条件积分和首拍保护；V3 将前馈/补偿后的最终 PWM 一并纳入处理 |
| 缺少系统性的非法数和物理范围收口 | V2 加入指令与配置校验；V3 补齐类型、组合和失败路径 |
| 红外没有逐通道有效性，任意障碍统一降速 | V2 识别无效通道并按行进方向过滤；V3 增加渐进限速与无效策略 |
| 在线零偏更新缺少窗口方差判据 | V2 加入方差窗口和相对显式标定值的窄幅内存自适应 |
| 速度 0% 被当成满速比例；转角精修折回 ±180° | V3 定义零目标速度并区分累计偏航和短角误差 |
| 位置 PID 与角加减速配置虽存在，但未完整进入控制路径 | V3 使用实际位置环和角加减速路径 |
| 心跳停机仅覆盖连续模式 | V3 对全部运动动作统一约束，并处理异步时间边界 |
| 配置写入结果未完整核实，舵机为 16 位 LEDC 配置 | V3 增加成功落库后发布及 14 位舵机绑定失败门控 |

单路 FG 本身不提供方向，历史代码按所下发的方向为计数加符号；外力拖动、惯性余转及接线反向需要额外验证。停止操作撤去 PWM，现有驱动接口不能保证主动制动或车体立即静止。

## 验证证据与使用建议

原始 README 记录曾在 `espressif32 6.9.0 / Arduino core 2.0.17` 下做语法与类型校验，但**本次历史恢复没有重新编译 V1.0，也没有补做上板测试**。该历史记录不等于当前工具链全量构建通过；V3 的新日志也不能用来证明 V1。

阅读和重用时应保留原始依赖、板型、分区和源码的对应关系。旧说明以 N16R8 和部分电池阈值为默认背景；实际板型、电池体系、调速电平、FG 电压和传感器型号须按装机确认。公开 AP 密码是开发默认值。

建议先读本页理解 V1 定位，再阅读 [V2.0](V2.0.md) 的安全加固和 [V3.0](V3.0.md) 的运动正确性、迁移与验证说明。历史工程保留用于对照和回退准备，最新交付入口始终以仓库首页为准。
