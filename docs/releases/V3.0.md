# V3.0 发布说明：运动正确性、失败处理与可验证交付

发布日期：2026-10-05 · 作者：HJZ · 许可证：[MIT](../../LICENSE)

**[下载 Arduino 完整工程](https://github.com/HJZ0810/Huabei-Wusheng-Gedou-Sai-ESP32-FangAn/releases/download/v3.0/CombatBot_V3.0_Arduino完整工程.zip)** · [安装与接线](../../新手安装与接线.md) · [验证记录](../../验收与验证.md)

V3.0 采用统一运动状态机、配置快照和连接协议，保留连续驾驶、精准距离/转角、标定、传感器及设置四页。重点使设置值和失败反馈更可信，使逻辑运动与电气方向一致，并让发布包对应已验证源码。

## 比较基线

本文比较 [V2.0 公开提交 fd650ac14d98aebc9779bf88365e23ad4cc5305f](https://github.com/HJZ0810/Huabei-Wusheng-Gedou-Sai-ESP32-FangAn/commit/fd650ac14d98aebc9779bf88365e23ad4cc5305f)，不是 V1 或其他同名本地工程。

V2 已有急停绕队列、CAS 控制权、输入校验、PCNT、换向等待、PID 条件积分和传感器有效性。V3 保留这些基础，补齐控制组合、协议和失败路径。旧行为描述来自对应源码及软件复现，不表示每台实车均发生过故障。

## 核心差异

| 项目 | V2.0 行为或边界 | V3.0 实现 | 使用收益 |
|---|---|---|---|
| 连续速度 0% | 0 被当作满速比例 | 0 为零目标速度 | 数值与驾驶意图一致 |
| 电气取反 | 影响逻辑反馈符号 | 电气极性与逻辑运动分离 | 前进/倒车/里程方向一致 |
| 航向修正 | 左右输出符号问题 | 按统一轮序和偏航方向纠偏 | 不推动同方向偏差扩大 |
| 整圈转角 | 偏航差折回 ±180° | 累计偏航与短角误差分开 | 正确表达 360° 和多圈 |
| PID 边界 | 自身抗饱和，前馈/补偿另加 | 按最终可用 PWM 处理积分，换向等待清理积分 | 减少限幅/等待阶段误差积累 |
| 转向与标定 | 部分参数未完整使用，IMU 精修可能掩盖转向比例 | 实际角加减速；正常转向与独立轮行程标定分开 | 参数路径与标定结果更可解释 |
| 舵机 LEDC | 16 位超出 S3 能力 | 50Hz / 14 位，检查失败 | 匹配硬件上限 |
| FG 计数 | 已有 PCNT/中断回退 | 四轮分别使用 S3 四个单元，展开回卷并验证失败路径 | 明确资源与 core2/3 兼容边界 |
| 保护设置 | 边缘/IR 独立开关，无统一总开关或倾倒项 | 增加总开关、倾倒和 IR 无效项，保留可调堵转并收紧范围 | 可分项调试，明确数据无效时的行为 |
| IR 保护 | 有方向过滤和有效性 | 渐进限速、无效策略；检查新指令、旧目标、实测轮速 | 换向时仍覆盖余转方向 |
| 加速度 | 已有加速度/冲击字段 | ADXL345 全分辨率 ±16g，MPU ±2g 替代来源及饱和 | 看清来源与量程限制 |
| 配置保存 | 未核实写入长度，页面可能忽略 HTTP 失败 | 候选校验 → 成功落库 → 发布，错误可见 | 不把未保存显示为成功 |
| 配置并发 | 缺少完整共享仲裁 | 等控制任务撤输出，再进入编辑窗口 | 覆盖已取走 stop 但尚未撤输出的窗口 |
| HTTP 身份 | 合成 REST 编号参与仲裁 | HTTP 绑定实际 WS 随机令牌，断线撤销 | 不能只凭广播 owner 冒用控制者 |
| 离页行为 | 旁观者也可能自动 stop | 自动停止仅由当前控制者触发 | 多开页面减少无意打断 |
| 时间判断 | 周期起点/异步采样边界 | 近期未来时间戳及 millis 回绕处理 | 避免新鲜反馈误判过期 |

### 保留的能力

停止/急停不受普通队列容量影响，代次使旧动作失效；急停后显式解锁。运动动作受控制者心跳约束，非控制者不能启动运动或代续心跳。手动 stop/estop 保持可用，自动失焦、切页及关闭按控制者身份触发。

FG 优先硬件计数，失败回退中断；换向仍要求距末次 FG 边沿至少 120ms 且滤波速度不高于 0.8cm/s。入口与配置层拒绝非有限数、错误类型和不合理范围。

AP 常驻，可配置 STA，网页和二维码离线可用。维护网页为完整可读源码；Arduino 内由工具生成 gzip 资源，发布前核对解压结果与网页一致。

## 优势与取舍

**控制更一致。** 轮序、距离、角度和输出单位在同一套模块中解释；标定、正常运动及补偿各有明确职责，接口初始化失败能够被识别。

**保存失败可追踪。** NVS 打开失败、写入不完整或候选校验失败时保留当前配置；快照与保存结果一致。标定结果在共享编辑仲裁内消费，避免重复应用。

**发布可复核。** 主机回归直接执行真实控制、采集和电机模块，另覆盖网页协议与错误响应。成功日志绑定源码哈希，打包核对 Arduino 导出、依赖和资源；源码改变后不能沿用旧凭据。

**依赖与维护清楚。** 固定 ArduinoJson 7.3.1、ESP32Async/AsyncTCP 3.3.2、ESP32Async/ESPAsyncWebServer 3.6.0，随包提供。传感器寄存器驱动不依赖 V2 的 Adafruit 组合。中文注释说明单位、前置条件与硬件限制。

以下是取舍，不能宣传为全面提升：

- **控制目标 200Hz → 100Hz。** 控制计算使用实际时间差；没有实车最坏时延或精度数据，频率变化不证明更快、更准。
- **总保护默认关闭。** 先确认接线再开启，避免未接传感器锁住初次调试；使用者必须主动完成保护设置。独立开关默认开启不等于总保护已启用。
- **严格 IR 无效策略默认开启。** 异常或超量程时拒绝相关方向；改为跳过会失去对应的数据异常保护。
- **有效低压仍限速 50%。** 不迁移严重低压停机阈值，不能根据“24V”推断电池体系，需硬件确认后设计。
- **网页修改需导出。** 编辑 `combatbot/web/index.html` 后重建嵌入及 Arduino 副本，以一致性换取可追溯交付；不推荐改生成数组。

## 升级与回退

1. V2 导出配置，记录实测机械、电池、电平参数，保留 V2 源码或固件。
2. 打开 V3 `CombatBotArduino/CombatBotArduino.ino`，使用当前三库依赖。不要复用旧根目录草图或 V2 客户端协议。
3. V3 使用 **`combatfusion`**，不读取或覆盖 V2 **`cbot`**；首次启动为 V3 默认。
4. **核对 IR 通道接线和安装角度。** V2 六路为前/后/左前/右前/左后/右后，V3 为前/右前/右后/后/左后/左前等角顺时针排列；斜向也由 ±45°/±135° 改为 ±60°/±120°。按下表迁移，不能只升固件或只换线。
5. 在 `combatbot/` 离线转换：

   ```powershell
   python scripts/convert_workbuddy_config.py "V2参数.json" "V3候选.json"
   ```

6. 阅读转换说明，以 V3 默认为基础，停车导入候选。候选不是验收配置，设备仍做范围和跨字段校验。**旧 `safetyEdge` 或 `safetyIR` 开启时，转换器推导 `safetyEnabled=true`，导入前核对全部传感器；首启默认关闭不代表迁移后仍关闭。**
7. 架起车体核对电气方向与逻辑反馈，再重做 IMU、行程和转向标定，最后低速落地验收。

| 不兼容点 | 迁移处理 |
|---|---|
| 速度 PID | V2 归一化占空比与 V3 PWM 计数输出不能直接共用，保留 V3 默认后调参 |
| 位置/航向环 | 控制组合改变，转换器不机械照搬 |
| 舵机 | 旧 µs 目标按端点转换为角度，端点仍为 µs；确认机械限位 |
| 零偏与运动比例 | 重新标定，转换字段仅为候选 |
| `batCrit`、旧 PWM 上限、附加平衡、主动刹车偏好 | 不迁移，转换说明列明原因 |
| REST/WS | 按 [V3 接口](../接口协议.md) 更新字段和握手，旧客户端不直接兼容 |

回退时刷回 V2；未清空 NVS 时 V2 仍读取原 `cbot`。V3 配置不反向导入 V2，应保留各自备份，同名字段也可能单位不同。

### 六路 IR 接线与方位迁移

下表通道编号从 0 开始；角度统一用**车前为 0°、从上方看顺时针为正**描述物理方位，不照搬旧源码的角度符号。

| 传感器方位 | V2 通道 | V3 通道 | V2 安装角度 | V3 要求角度 |
|---|---:|---:|---:|---:|
| 前 | 0 | 0 | 0° | 0° |
| 后 | 1 | 3 | 180° | 180° |
| 左前 | 2 | 5 | −45° | −60° |
| 右前 | 3 | 1 | +45° | +60° |
| 左后 | 4 | 4 | −135° | −120° |
| 右后 | 5 | 2 | +135° | +120° |

因此映射为 **0→0、1→3、2→5、3→1、4→4、5→2**，同时应按 V3 要求调整四个斜向探头的安装角度。只调整通道而仍以旧角度安装，会使方向保护和网页雷达的方位假设不一致。若机构无法调整，应先修改并验证适合实际安装的方向模型，再使用保护；当前发布固件没有任意安装角度配置。

完成接线和方位调整后，静止逐路遮挡/接近探头，确认网页对应方位、有效性和距离；架起车体检查前进、后退、换向与旋转的保护选择，再低速装机验证。不能用网页图标正确代替物理方位确认。完整接线见 [新手安装与接线](../../新手安装与接线.md)。

## 验证与边界

最终双版本编译及回归结果以 [验收与验证](../../验收与验证.md) 和 `combatbot/test-artifacts/release-evidence.json` 为准，避免重复数字漂移。覆盖控制器、配置失败、电机 core2/core3、真实采集、会话、网页、转换器及导出一致性。

本版未烧录、未上板。主机替身、确定性交错与编译成功不能证明多核最坏时延、NVS 掉电一致性、传感器曲线、机械精度和停车距离。仍需实际验收 100cm、90°、360°、换向、弱网、低压、边缘、倾倒和堵转。

现有接口只有方向与调速，停车为 **撤 PWM**，不能保证主动刹车或车体 100ms 内静止。冲击只提示；令牌用于连接绑定而非账户认证。软件通过不等于实车或量产验收。
