# V4 控制扩展设计（只读审查）

> 设计阶段归档：以下保留当时的调研、候选方案和待确认事项，不是最终部署指南；最终采用单车专属控制链接、无账户/选车、独立域名 combatbot.luo-jin-ai.com，自主任务断云继续，控制权需手动接管。当前功能与证据见 [V4发布说明](../../docs/releases/V4.0.md)，公网配置与回退见 [服务器部署](../../docs/setup/V4服务器部署.md)。


日期：2026-10-05。基于 `combatbot` 的 V3 实现；不修改现有固件。

用户已接受：仅使用现有传感器、估计定位、置信度与人工起点；活动范围包含外围低层；可能采用正面冲击台阶登台，无坡道。用户尚未装车，已授权设计安装：四灰度向下四角，三E18向下前左/前右/后中，周向IR水平向外。

## 复用边界

`controller.cpp::run()` 是唯一控制任务，负责采样、积分、命令消费、输出及快照。V4 自主模块必须在该任务中执行，不另建写电机的任务、不向自己的队列反复投递 Move/Turn。复用末端轮速斜坡、PID、换向等待、堵转、急停代次、配置准入。

`stopMotion()` / `fault()` 应同时清自主动作、登台过程、控制授权；重启、急停、失联不能隐式恢复自主。人工接管在命令门控中做原子模式撤销与代次更新，再受理人工动作，不让两个来源同时输出。

当前 owner/heartbeat 约定把所有运动绑定到连接；自主模式是否离页继续要由父代理确认，不能偷偷给自主任务伪造心跳。建议保留显式有限期授权与最高连续运行时长；网络断开按最终约定撤销。云端消息只能到同一命令门控。

## 数据模型与单位

采用 cm、s、°；地图中心 `(0, 0)`，X 向图右、Y 向图上，航向从 +X 逆时针为正。人工起点设置世界航向偏置，不改累计 `t.yaw`，避免影响 V3 多圈转角。

```cpp
enum class Floor : uint8_t { Unknown, Lower, Upper, TransitionUnknown };
struct PoseEstimate {
  float xCm, yCm, headingDeg;
  float uncertaintyCm, headingUncertaintyDeg; // 启发式误差规模，不是实测精度保证。
  uint32_t updatedMs, anchoredMs;
  Floor floor;
  bool anchored, valid;
};
struct BodyDemand { float forwardCmS, yawDegS; };
enum class DigitalRole : uint8_t { Unassigned, FloorPresence, BoundaryBrightness, Enemy };
struct ProbeMount {
  DigitalRole role;
  float forwardCm, leftCm;
  bool ready;
};
```

数字 role、探头位置与安装有效电平分别配置；不能把 `gray=true` 当通用掉台事实。AP连接方式保持兼容，但人工与自主都应按新向下安装方案解释危险：E18归一化 active=true 表示见地，危险为 !active，不能沿用V3 `sensorEdge()` 的 e18=true 即危险，否则正常地面会使车锁死。

## 默认安装方案与可配置坐标

安装坐标用车体前F、左L、上Z，与世界X/Y独立。车身参数以轮胎、铲面与刚性附件的实测运动外包络为准。未测量前提供长260 mm、宽240 mm的设计示例，并显著标记“待实测”；不是原机械仓库已确认尺寸。采用以下公式，修改车身半长A/半宽B后自动重新显示安装建议。

| 设备 | F / L 坐标建议 | 示例坐标（mm） | 探头端面高度 |
| --- | --- | --- | --- |
| 灰度0：左前 | A+15 / B-10 | 145 / 110 | 离当前支撑面8～12 mm，可调 |
| 灰度1：右前 | A+15 / -(B-10) | 145 / -110 | 同上 |
| 灰度2：左后 | -(A+15) / B-10 | -145 / 110 | 同上 |
| 灰度3：右后 | -(A+15) / -(B-10) | -145 / -110 | 同上 |
| E18 0：左前见地 | A+50 / B-25 | 180 / 95 | 端面向下、离支撑面约60 mm，可调 |
| E18 1：右前见地 | A+50 / -(B-25) | 180 / -95 | 同上 |
| E18 2：后中见地 | -(A+50) / 0 | -180 / 0 | 同上 |

E18例子旨在给探测位置约50 mm车身提前量；它是可调反射式开关，不是测距仪。正常高度约60 mm、落差后约120 mm只是需验证的两种场景，不能自动推出“把旋钮设90 mm即可安全”。在黑、白、红、黄、蓝贴纸及比赛照明下，正常地面应连续可靠见地、同材质6 cm落差处应连续可靠失地。若两类响应重叠，必须调整高度、遮光、角度/位置；仍无法区分则自主准入拒绝，不能忽略输入继续行驶。

前方探头不能被铲遮挡，不应与车轮包络相交；支架要圆角、可退让、走线固定，避免刚性长悬臂在碰撞中成为伤害点或损坏传感器。灰度不是向下测距，只提供亮暗候选；需在所有场地颜色上采集触发结果，不将黄/蓝/红自动认成掉台。

IR按现有6路前、右前、右后、后、左后、左前或12路30°等间隔水平向外；端面建议离支撑面80 mm并低于200 mm围栏。各探头实际F/L偏置及朝向可配置，安装时避开铲、轮、相邻探头反光。80 mm高度通常看不到60 mm台阶侧面，不可依它进行爬台接触/越台判定。

默认自主预算建议保守：搜索12 cm/s、有限推撞18 cm/s、登台尝试20 cm/s。登台默认尝试可能因机械能力不足而失败，不能为了提高“成功率”自动提速。安全速度应满足 `探头提前量 > v×实测采样响应时间 + 实测撤PWM后滑行距离(v) + 安装余量`；PID配置deceleration仅限制目标，不是实际机械刹车能力。用户实测前自主默认关闭。

## 最小纯 C++ 模块接口

建议独立 `arena_model.h`、`pose_estimator.h/.cpp`、`arena_safety.h/.cpp`、`autonomy.h/.cpp`。使用固定容量、按值 POD 输入，不依赖 Arduino、RTOS、JSON、网络，不动态分配，生产与 host 测试复用同一实现。

```cpp
bool validateArena(const ArenaConfig&, ArenaError&);
Zone classifyZone(const ArenaConfig&, float xCm, float yCm);
bool setPoseAnchor(PoseEstimate&, const PoseAnchor&, const ArenaConfig&, uint32_t now);
void integratePose(PoseEstimate&, const OdometryStep&, const EstimatorConfig&);
bool applyBoundaryConstraint(PoseEstimate&, const BoundaryObservation&, const ArenaConfig&);
EdgeDecision assessEdges(const ArenaFrame&, const BodyDemand&, const ArenaConfig&);
TargetCandidate detectTarget(const ArenaFrame&, const ArenaConfig&);
AutoDecision tickAutonomy(AutoState&, const ArenaFrame&, const ArenaConfig&);
void cancelAutonomy(AutoState&, StopReason);
```

`ArenaFrame` 含 PoseEstimate、传感器数据/逐类时间戳、输出/轮速、必要探头可用性及当前时间；`AutoDecision` 仅产出 BodyDemand、状态、停止原因、层面待确认标志。电机实现只能由控制器消费 demand。

## 分层地图

外场边长380 cm、台面边长240 cm作为可修改默认几何；Lower 是外围环带，Upper 是中心台面。地图坐标与“车已在哪层”是不同信息，不能用估计点进入中心正方形就宣告登台。

Lower 导航需把整个中心台面膨胀为障碍；仅指定、人工核实的登台入口可以进入尝试区。Upper 导航以台边向内缩 `bodyRadius + safetyMargin + uncertainty` 形成保守活动区。未知/过渡层禁止普通自动导航与进攻，保留停止、人工修正与有界恢复。

外场启动区坐标、50/40 cm轴向尺寸、白边宽度应可配置并标为未核实；绘图默认只用可确定的方形几何，不添加无来源坡道。

地图是辅助预测，局部必要探头危险始终优先。误差扩大到无法证明整个车身在指定可行区时，自主先停止等待人工锚定；禁止把坐标 clamp 到地图内，这会隐藏真实越界。

## 位置估计与质量

V3 已计算四轮脉冲增量 `delta`、均值行程 `ds` 与融合偏航。V4 用航向中点积分：`x += ds*cos(thetaMid)`，`y += ds*sin(thetaMid)`。始终保留多圈偏航，仅显示时归一化；避免用累计 `t.odo` 重复积分。

误差规模随行程、转角、离人工锚定时间增长；IMU无效、轮间明显不一致、轮偏航/陀螺差过大、冲击或加速度饱和时增加误差或使 pose invalid。冲击后即使脉冲看似正常也不能保持“高可信”。无真实误差统计时质量只标高/中/低及误差模型估计，不写95%置信区间之类伪概率。

人工初始点、修正点均需停车、明确层面、有限数值与地图范围；修正更新独立定位原点和代次，不重置控制器脉冲/动作反馈。关闭网络不能保存未经确认的位姿并在下次启动自动使用。

边界修正只在已知对应边、有效探头位置、方向匹配、预测误差范围内唯一候选且连续稳定时使用，可只修一个坐标。单个亮暗事件、黄蓝/红图案都不能证明边身份。IR候选墙面修正需符合可见性、20～150 cm有效量程、传感器高度与地图射线匹配；未知高度或对手遮挡时不启用。不能为改善估计强行将目标读数当墙。

## 采集层扩展

`sensors.cpp` 当前数字输入每20 ms轮询、候选稳定后提交；默认30 ms去抖可能让首次危险响应达到约50 ms，再加调度及机械余转。100 cm/s 下只该部分就约5 cm，不能凭当前配置保证防掉。

建议保留去抖后的状态用于UI，同时输出必要边缘输入的原始归一候选、数字实际采样时间、是否初始化完成。危险置位可用单向快路径，解除需稳定；在安装角色未确认时不改变极性和阈值。反射/地面缺失的物理判据由 `DigitalRole` 解释。

添加逐路IR时间、数字实际时间及IMU实际时间，避免只依 `sampledMs=每次调用时刻` 误认为所有缓存同时新鲜。采集失效与“没有检测到敌人”区分；远场IR无效不能解释为无障碍，也不能默认强制要求全周IR有效，因为场地天然超量程。

## 边缘与格斗安全

把 IMU/电机故障、时间超限、严重倾倒保留硬停止；不要直接在 `sensorFault()` 中对自主边事件全部锁定，否则撤离状态永远无法动作。自主 `assessEdges()` 可产出 `Stop / Escape / Continue`，必要地面探头缺失或前后同时危险产出Stop。

Escape 根据触发探头的车体位置及可行方向选择低速撤离，限时限距，遇另一侧危险停止，禁止盲目固定后退。多次失败进入人工确认；先撤PWM，再等换向等待允许反向，不能跳过电机层保护。

在已核实台面层，外围白边可以成为辅助风险信号，但必须结合探头角色与地图预测，不能把任何亮值当边缘。外围低层的台阶接近与上层的台阶离开属于不同语义。

IR在格斗模式可用于目标候选方向/距离；未知物体不宣称就是对手。靠近目标不应沿用V3全局近障碍停车，但只在有效候选方向、有界攻击、必要防掉探头有效时允许对应近障碍进入推撞；其它方向/模式保持普通策略。防掉、失效和急停不因攻击而豁免。

## 有界登台（待安装与机械确认）

可编程尝试不等于机械具备爬6 cm直阶能力。需要用户确认铲面/底盘机构、入口方向、车体尺寸、探头支撑语义、尝试速度/时长/行程上限。

建议阶段：到达低层入口 → 对正并停稳 → 有界接触/爬阶 → 候选越顶 → 停稳待层面确认。需要 IMU有效、安装轴已核实、必要地面探头可用、有限预算；任一保护触发、进展超时、无轮反馈、过大倾角或采样失效立即撤输出、取消自主授权。无需未测量的“成功冲击力度”配置，不绕过换向保护或堵转。

MPU/ADXL可以提供的相对证据是：低动态时倾角升高、随后倾角回落稳定、必要向下探头持续见支撑、FG有预期方向进展。加速度饱和/冲击区间暂停姿态证据累积。机身安装方向若只有Z朝上确认，可估算无方向总倾角；要区分俯仰方向必须再确认车体X/Y轴映射。不能把瞬时加速度当重力来判倾角。

同样事件链可由撞墙、被顶起或其它起伏产生；现有器件不能直接测6 cm高度。FG路程/计时/姿态链达到阈值只能发布 `climb_candidate`，层面保持 `TransitionUnknown` 并停止，网页允许用户确认已上台后设Upper；不能自动进入高台攻击并显示成功。失败退回只在后方支撑有效、姿态允许且人工/程序恢复授权成立时执行有界低速动作，否则保持停止。

## 配置及验证扩展点

`types.h::Config` 增自主开关默认关闭、场地参数、探头映射、车身余量、误差预算、动作预算及登台入口；`config.cpp` 宏清单、严格JSON键、有限范围、交叉关系、NVS先保存再发布全部同步。未知映射必须使自主准入拒绝；配置不能用默认“猜测已安装”隐藏前置条件。

`Telemetry` 增世界位置、层面、质量与原因、轨迹序号、自治状态/预算/目标候选及上台待确认。短轨迹可由网页采样绘制，不将不断增长数组塞进固件快照。

最小测试：纯算法直行/反向/转弯/多圈与dt异常；冲击/失效质量降级；层面与几何不一致；敌人遮挡不纠正位置；所有探头方位逃生及双侧危险；候选过期；推撞超预算/必要传感器失效；登台事件不足、动态加速度、计时/FG不能单独确认为上台；人工接管/急停立即撤自主并使旧命令失效。

现有 `test_controller.cpp` 直接包含生产实现、虚拟时钟/脉冲/传感器，可继续注入真实控制任务验证；现有 `test_sensor_model.cpp` 可覆盖新增时间戳/单向快判/初始化与IO掉线；`test_config.cpp` 覆盖新字段类型、范围、持久化失败。随后沿用2.0.17与3.3.12双编译及哈希证据门控。所有测试只证明软件逻辑，不证明实际爬台、避边距离或定位误差。
