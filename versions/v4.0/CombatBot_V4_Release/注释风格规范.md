# CombatBot 中文注释规范

这套工程采用“详细说明 + 清晰分区”的风格：读文件头能理解模块位置，读接口说明能正确调用，读关键算法能理解公式、单位与取舍。注释服务于交接和维护，写实际实现，不填写虚构的作者、版权、保密等级或修改历史。

## 1. 文件头：交代职责和边界

所有项目自有固件模块使用 Doxygen 文件说明，固定分隔线让不同文件保持一致的阅读节奏。

```cpp
/**
 * @file    motor.cpp
 * @brief   四轮电机调速、单相 FG 采样与舵机输出。
 *
 * ============================================================================
 * 模块职责
 *   将带符号 PWM 请求转换为方向与调速输出，维护累计脉冲与轮速估计。
 *
 * 运行约定
 *   初始化后由控制任务顺序调用采样和输出，不提供任意线程并发访问能力。
 *
 * 设计边界
 *   单相 FG 不携带方向，计数符号由实际施加的方向推定。
 * ============================================================================
 */
```

`.ino` 文件头使用导出后的实际文件名；资源头明确标记“自动生成”和维护入口。第三方二维码库保留原有作者与许可证说明。

## 2. 接口：说明调用者必须知道的约定

用 `@brief` 概括用途，用 `@param`、`@return`、`@pre`、`@note` 说明单位、范围、输出、前置条件和副作用。只保留有实际信息的标签，不为排版填入空洞的“无”。

```cpp
/**
 * @brief 按编码器增量更新四轮速度估计。
 * @param[in] dt 两次采样之间的时间，单位 s。
 * @param[in] cfg 当前配置快照，标定脉冲/厘米优先于理论换算。
 * @param[out] pulses 四轮累计带符号上升沿计数。
 * @param[out] speed 四轮滤波线速度，单位 cm/s。
 * @param[out] rpm 四轮估计转速，单位 rpm。
 * @note 四轮数组顺序固定为左前、右前、左后、右后。
 */
```

公共头文件重点写调用契约，定义处重点写执行过程。简单状态读取用短注释，复杂状态机用编号阶段，避免每个函数都重复相同长段落。

## 3. 算法：写公式、维度和设计原因

- 尺寸用 mm，行程与线速度用 cm、cm/s，加减速度用 cm/s²。
- 累计偏航用 °，角速度和零偏用 °/s，舵机脉宽用 µs。
- PPR 是输出轴每圈的 FG 上升沿事件数；四轮标定使用绝对脉冲增量的平均值。
- 梯形规划说明 `v² = 2ad` 的使用条件；几何转向说明毫米到厘米换算。
- 状态与并发说明谁拥有状态、谁发请求、快照何时发布、旧队列何时失效。

局部说明写在复杂逻辑之前。说明“为何如此”与“何时成立”，不重复 `i++`、赋值或函数名字面含义。

## 4. 表述：把估计、请求和实测区分开

| 概念 | 本工程的注释要求 |
|---|---|
| 10ms 控制周期 | 写为调度目标；同步 I²C、锁等待与任务调度可能造成超期 |
| Stop/ACK/202 | 写为请求登记或受理成功，不等同已经执行完毕 |
| PWM=0 | 写为撤去驱动，不称为独立主动刹车或机械停稳 |
| 编码器方向 | 写为由已施加方向推定，不能识别外力推动方向 |
| 参数范围校验 | 防止非法输入，不证明范围内每个值适合这台车 |
| 静止零偏更新 | 写明观测条件和不可识别缓慢旋转的限制 |
| IR 有效标志 | 写明范围和缓存条件，不把无效数据解释为无障碍 |
| 硬件/网络状态 | 写实际检测项，不把软件探测成功写成全链路可靠性保证 |

融合版新增行为必须同时更新接口说明、配置单位与失败路径。详细实现说明写在源代码中，网页只展示用户作决策需要的含义。

## 5. 维护与同步

维护源位于 `combatbot/src`、`combatbot/include` 和 `combatbot/web/index.html`；修改后运行 `scripts/export_arduino.py` 同步 Arduino 草图，再运行 `scripts/package_delivery.py` 更新交付包与 SHA256 清单。不要单独修改自动生成的 `web_asset.h` 或仅修改导出的副本。

原版的注释编辑曾使用 token 比较核对；融合版包含实际功能改动，不能继续声称可执行代码不变。当前交付使用完整编译、真实模块主机回归与网页契约验证，并把成功结果绑定到源码 SHA256；这些检查不代替硬件测试。
