## V4 的进步与取舍

进步在于把“控制请求、车端自主、云连接与地图展示”分清职责，同时沿用单控制任务与急停路径。自动入场和目标导航受到层面、车身、安全余量、误差及任务期限共同约束；登台结果明确为 `upper_estimated`，不会伪称绝对位置已确认。白蓝网页减少入口步骤；专属链接直接建立单车会话，驾驶权仍需手动接管。切换链接清旧会话及租约，旧Socket事件和迟到认证响应不恢复旧身份。

定位仅使用现有传感器。FG 打滑/外力推动车、惯性漂移、测距盲区和颜色反射仍会影响估计；数字灰度不能识别颜色或测高度，E18 不是准确测距。当前不提供自动绝对坐标重定位，不以渲染流畅证明实车精度。

“暴力冲台”转化为有界尝试，不绕过支撑风险、急停、换向或堵转，也不无限加速重试。软件编译和仿真通过不能证明底盘、铲面和轮胎能够爬上 6 cm 直阶，撤 PWM 也不保证主动制动。

## 依赖与编译分区

V4固定四个依赖：ArduinoJson7.3.1、ESP32Async/AsyncTCP3.3.2、ESP32Async/ESPAsyncWebServer3.6.0、WebSockets2.7.2附随包审计补丁。WebSockets补丁适配core2/core3超时单位、强制CA验证、限制帧大小和TLS握手；保留原版权、LGPL 2.1、原始/修改哈希及补丁脚本；两份修改文件WebSocketsClient.cpp/WebSockets.h顶部列明修改者、2026-10-06日期与具体变更，满足逐文件修改声明要求。确定性依赖ZIP和版本清单同步记录补丁来源，脚本幂等且拒绝未知SHA。不要用库管理器未补丁原版替代。

V4首轮草稿在core3默认1.25MB APP已超容（1,381,440 / 1,310,720 B，非最终源码容量），最终验证采用 `esp32:esp32:esp32s3:PartitionScheme=huge_app`。4MB Flash示例拥有3MB APP而无OTA；N16R8依真实模组选择16MB/OPI及3MB APP菜单。此变化是容量需求，不代表默认分区成功，也不以静态RAM报告推断运行内存峰值。

## 首次启用与升级

1. 保留 [V3 固定源码](https://github.com/HJZ0810/Huabei-Wusheng-Gedou-Sai-ESP32-FangAn/tree/v3.0) 与当前参数导出；V1/V2/V3 完整版本记录继续保留。
2. 按 [V4 安装与校准](../hardware/V4传感器安装与校准.md) 装车。默认 26 × 24 cm 是待实测车身初值，设置正确外包络、入口和低速预算。
3. 核对 E18 电平语义：归一化 `true` 见地、`false` 缺地；向下安装不再沿用旧版“有效触发即危险”的理解。不得直接凭旧参数启用自主。
4. 在本地完成标定与保护核对后启用 `arenaEnabled`、`arenaCalibrated`；确认爬阶方案再启用 `arenaClimbEnabled`。三个字段默认均为 `false`。
5. 停车设置人工起点/航向/层面。低层格斗或高台目标会走完整入场链；独立登台任务完成后停稳。
6. 配置STA、独立云设备凭据和可信CA后启用云功能。云主机为`combatbot.luo-jin-ai.com`，端口443，路径`/ws/device`；使用仓库外的专属链接打开单车网页，无需账号、输入或选车。AP操作保留；只有STA实际联网时才建立远程连接，网络访问不会替代本地校准步骤。

回退请使用对应标签的完整固件和匹配参数。V4新增的向下探头语义、云配置、自主授权及层面不能假设旧固件支持。升级或重启不会自动续跑自主任务。
