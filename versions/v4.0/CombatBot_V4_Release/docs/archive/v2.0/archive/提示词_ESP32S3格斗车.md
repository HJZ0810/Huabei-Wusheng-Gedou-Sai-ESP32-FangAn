# 一、任务目标
为一台 3.5kg 四轮差速（坦克转向）格斗机器人，实现一套基于 ESP32-S3 的无线控制系统：

FG 每轮转脉冲数按 90 预估（9 脉冲/电机转 × 10），最终以行程标定实测为准。

# 三、硬性约束（违反即为错误方案）

1. **禁止使用 TB6612 / L298N / 任何 H 桥驱动**。JGB37-3625 是无刷电机且自带驱动板，正确驱动方式是「方向 IO 电平 + 调速 PWM」，不是 H 桥。
2. **FG 是单相脉冲，无方向信息**。转速由脉冲频率测得；旋转方向必须由 MCU 自己下发的方向指令记住（维护一个 dirSign 符号位，计数时带符号累加）。
3. **FG 为 5V 电平**，必须经电阻分压（建议 1kΩ + 2kΩ，5V→3.33V）或经电平转换器降到 3.3V 后再进 ESP32 引脚，否则烧毁 IO。
4. **蓝线调速信号为 0~5V**。ESP32-S3 的 PWM 是 3.3V，必须经双向电平转换器抬升到 5V；建议在电平转换器输出端加 RC 低通（1kΩ + 0.1µF，fc≈1.6kHz），用 20kHz PWM 生成平滑直流调速电压。
5. **开 WiFi 时 ESP32-S3 的 ADC2 不可用**，全部模拟量只能使用 ADC1（GPIO1~GPIO10）。因此红外测距必须走 CD74HC4067（只占 1 个 ADC1 引脚 + 4 个地址脚）。
6. **AP 热点永不关闭**。上电即开 AP；STA 连接成功后 AP 继续保持；STA 断开立即回落（AP 仍在）。两种网络状态下网页都要能设置参数与操控。
7. **GY-291 没有陀螺仪**，不能用于测偏航角。它只用于：倾角/被撞翻检测/冲击检测/振动监测。偏航角必须来自 MPU6050 的 Z 轴角速度积分，并与 FG 里程计融合。
8. 前端必须是**单文件内嵌网页**（HTML+CSS+JS 全部打进固件，无外部 CDN、无外网依赖，AP 模式下断网也能用）。
9. 所有配置必须持久化到 **NVS / Preferences**，掉电不丢。

|---|---|
| CD74HC4067 模拟输出 SIG | GPIO4（ADC1_CH3） |
| CD74HC4067 地址 S0/S1/S2/S3 | GPIO5 / GPIO6 / GPIO7 / GPIO8 |
| I²C SDA / SCL（MPU6050 + ADXL345 + MCP23017 共用） | GPIO9 / GPIO10 |
| 舵机 PWM | GPIO11 |
| M1 左前：DIR / PWM / FG | GPIO12 / GPIO13 / GPIO14 |
| M2 右前：DIR / PWM / FG | GPIO15 / GPIO16 / GPIO17 |
| M3 左后：DIR / PWM / FG | GPIO18 / GPIO21 / GPIO38 |
| M4 右后：DIR / PWM / FG | GPIO39 / GPIO40 / GPIO41 |
| 备用（可做电池检测、蜂鸣器、额外传感器） | GPIO1 / GPIO2 / GPIO42 / GPIO43 / GPIO44 / GPIO47 / GPIO48 |

MCP23017 端口分配：GPA0~GPA3 = 灰度 1~4；GPA4~GPA6 = E18 光电开关 1~3。
CD74HC4067 通道分配：CH0~CH5 = 红外测距 1~6；CH6 = 电池电压（经 100kΩ+10kΩ 分压）；CH7~CH15 预留。
电机 PWM 使用 LEDC 外设：20kHz、10-bit（0~1023）。FG 计数使用 PCNT 硬件计数单元（若库不支持则用 attachInterrupt + CHANGE 双边沿计数）。
方向线逻辑：白线悬空/高电平 = CCW，接低电平(≤0.6V) = CW。

# 五、功能需求

## A. 网络与寻址
- 状态机：`BOOT → AP_ONLY → (尝试 STA) → AP_STA → (STA 掉线) → AP_ONLY`，**AP 始终开启不关闭**。
- AP：SSID `CombatBot-AP`（可配），密码可配（默认 `12345678`），网关 192.168.4.1。
- STA：SSID/密码在设置页填写；连接失败或掉线后每 15s 重试一次，期间 AP 不受影响。
- mDNS：主机名 `combatbot`，同时注册 `_http._tcp` 服务（端口 80）。无论在 AP 还是 STA 模式，`http://combatbot.local` 都要能访问；页面上同时显示当前实际 IP 作为兜底。
- 建议启用 Captive Portal（DNSServer）：手机连上 AP 后自动弹出控制页。
- 页面提供二维码（用 JS 纯前端生成，指向当前访问地址），方便扫码。

## B. 模式一：连续实时控制（按住即走，松开即停）
- 虚拟摇杆输出 (x, y) ∈ [-1, 1]；死区 0.08；指数曲线 expo = 1.5 提升小幅度精细度。
- 速度滑条 0~100%，调节的是**最大速度上限（cm/s）**，不是 PWM 占空比。
- 控制链路：按下 `pointerdown` → 立即发 start 指令 → 运行期间每 200ms 发一次心跳 → `pointerup` / `pointercancel` / 页面失焦 / WebSocket 断开 → 立即停车。
- 支持 PC 键盘：W/A/S/D 或方向键，空格 = 急停。
- 支持差速混合：摇杆 Y = 前后，X = 转向（左右轮速差）。

## C. 模式二：定点精准控制（一次性动作）
- 输入「前进 xx cm」（支持负值后退）与「左/右转 xx 度」，点一次执行一个完整闭环动作。
- 运动学（必须按此实现，D=轮径，T=轮距，C=πD）：
  - 目标脉冲数（直线）：`N = (s / C) × PPR`
  - 原地转向（左右轮等速反向）：单侧轮行程 `s = θ(rad) × T / 2`，`N = θ × T × PPR / (2 × C)`
  - 绕单侧轮转向：外侧轮行程 `s = θ × T`
  - 给定半径 R 的弧线：`v_left : v_right = (R - T/2) : (R + T/2)`
  - 轴距 L 不进入原地转向公式，但显著影响打滑量，故引入可标定的「转向打滑系数 K_turn」。
- 必须使用**梯形速度规划**（加速度限制 → 匀速 → 减速到位），禁止直接满速启动/急停。
- 三级闭环：
  1. 位置环：目标脉冲数 − 累计带符号脉冲数 → 输出目标速度；
  2. 速度环：目标速度 − FG 实测速度 → PID → PWM；
  3. 航向环：目标角度 − 融合偏航角 → 输出左右轮差速补偿；直线行驶时用左右轮脉冲差做跑偏修正。
- 动作完成后回传「目标值 / 实际完成值 / 误差」，在页面上显示。
- 提供快捷预设按钮：10 / 30 / 50 / 100 cm，45° / 90° / 180° / 360°。

## D. 传感器与遥测
- 以 10~20Hz 通过 WebSocket 推送遥测：四轮转速、线速度、累计里程、融合偏航角、电池电压、6 路红外测距、4 路灰度、3 路光电开关、三轴加速度、当前网络模式、RSSI、当前动作状态。
- 传感器页可视化：红外测距扇形雷达图（Canvas 绘制）、灰度四路灯、E18 三路灯、姿态小球。
- 安全联动（可开关）：光电开关/边缘检测到悬空 → 自动刹车；红外测距小于阈值 → 限制该方向速度。

## E. 设置页（必须精美、分组、带校验）
分组与字段：
1. **网络**：AP SSID / AP 密码 / STA SSID / STA 密码 / STA 启用开关 / mDNS 主机名。
2. **机械**：轮直径 D(mm) / 轴距 L(mm) / 轮距 T(mm) / FG 每转脉冲数 PPR。
3. **标定**：行程标定（输入实测距离，自动解算「脉冲数/厘米」）、转向标定（命令转 360°，输入实测角度，自动反解 K_turn）、IMU 零偏一键标定（静止 3 秒采样求平均）。
4. **运动**：最大速度(cm/s)、默认速度、加速度上限、减速度上限、转向最大角速度。
5. **PID**：速度环 Kp/Ki/Kd、位置环 Kp/Ki/Kd、航向环 Kp/Ki/Kd、互补滤波融合系数 α（IMU 与里程计权重）。
6. **电机**：每个轮子单独勾选「极性反转」、左右轮速差补偿系数、PWM 死区（克服静摩擦的最小占空比）。
7. **传感器**：灰度阈值、红外测距报警距离、E18 触发逻辑、安全联动开关。
8. **舵机**：中位脉宽、最小/最大脉宽、举铲角度、放铲角度。
9. **安全**：心跳超时时间(ms)、低压报警阈值(V)、失联动作（刹车/惰行）。
操作：保存（写入 NVS）、恢复默认、导出 JSON、导入 JSON、重启设备、清除 WiFi 配置。

## F. 安全（必须全部实现）
- 上电默认：所有电机 PWM=0，舵机回中，禁止任何自启动动作。
- 心跳看门狗：超过设定时间（默认 1000ms）未收到心跳 → 立即停车。
- WebSocket `onclose` / 页面 `visibilitychange` / `beforeunload` → 立即发停车。
- 红色急停按钮（常驻顶栏，任何页面可见，单击即停并锁定，需再次点击解锁）。
- 低压保护：电池电压低于阈值 → 页面告警并限速。
- 堵转保护：某轮 PWM 高但 FG 无脉冲持续 >1.5s → 判定堵转并停机告警。
- 舵机行程限位，禁止超出机械极限。

# 十、验收标准
1. 任意状态下（含 STA 连不上、STA 掉线、配置错误）AP 都能被搜到并连上，且能访问控制页。
2. AP 与 STA 两种模式下 `http://combatbot.local` 均可访问。
3. 连续模式：按住响应延迟肉眼无感（端到端 ≤80ms），松开 ≤100ms 内停止。
4. 精准模式（标定完成后，硬质平地）：前进 100cm 误差 ≤ ±2cm；原地转 90° 误差 ≤ ±3°；连续转 360° 累计误差 ≤ ±8°。
5. 断网/关页面后 ≤1s 内小车自动停车。
6. 所有设置项修改后保存、重启仍生效（NVS 持久化验证）。
7. 无任何外网依赖：拔掉路由器、纯 AP 直连时网页功能完整。
8. 代码可编译通过、无阻塞主循环的 delay、WebSocket 与电机控制互不阻塞（建议电机/传感器任务跑在独立 core 或 FreeRTOS 任务上）。

# 十一、已知工程坑（请主动规避并在代码注释中标注）
1. 24V 大电流电机与 ESP32 必须共地但电源分离，电机侧加 470µF+ 电解与 0.1µF 陶瓷去耦，必要时加续流/吸收回路，否则电机启停会复位 ESP32。
2. ADC2 与 WiFi 冲突 —— 只用 ADC1。
3. FG 无方向信息 —— 必须软件维护方向符号，否则计数只增不减、里程完全错误。
4. 高摩擦驼峰轮转向阻力极大，易打滑 —— 必须依赖转向标定系数 K_turn 与 IMU 融合，纯理论公式不可用。
5. MPU6050 零偏随温度漂移 —— 提供一键零偏标定，且长时间动作中做静止零偏更新。
6. Android 对 mDNS(.local) 解析不稳定 —— 页面必须同时显示 IP 并提供二维码兜底。
7. LEDC 通道数量有限（8 路）—— 4 电机 + 1 舵机 = 5 路，注意留余量。
8. 24V 电池满电约 25.2V、亏电约 21V，分压比与阈值要按此范围设计。
