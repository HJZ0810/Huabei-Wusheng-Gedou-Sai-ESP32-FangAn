# 版本资料维护约定

1. 根 README 保留全部已发布版本的展开式更新记录。新版本加入“完整版本更新记录”顶部，旧记录只补充和勘误，不删除、折叠或以最新版本覆盖。
2. `versions/` 中的原始工程快照只读，源码、原始 README、许可证和文档应与 `SOURCE_MANIFEST.json` 对应的 Git 基线一致。扩写说明放在 `docs/releases/`，不要修饰历史源码来制造旧版本的能力。
3. 升级到后续版本前，保留被替代版本的源码与文档，新增快照和来源清单；不要将已有 `versions/` 递归复制到新快照中。历史标签不移动，不强推覆盖。
4. 当前 Arduino 草图和旧版草图分目录保存，主 `.ino` 与各自目录同名，避免重复模块参与当前固件编译。
5. 版本对比以具体提交为基线，分清继承、修复、新增和取舍。未经重新执行的历史编译、实车性能和验收不能写成当前验证结果。
6. 文档和历史资料更新不改变当前固件或测试源码。若确需改变 `combatbot/` 的验证输入，按原验证工具重新生成凭据；不得修改哈希或沿用不匹配的成功日志。
7. 完整交付使用 `python tools/package_history.py`；该工具先调用当前打包门控，再收录历史快照并核验 ZIP 与 SHA256。发布时保留旧版本入口和资料，并核对 GitHub 实际附件名称。
