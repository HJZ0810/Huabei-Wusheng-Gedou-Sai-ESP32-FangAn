本次3.3.12由CLI采用增量模式，按依赖重新编译改动模块并完成链接。最终成功日志、源码哈希和实际构建输入逐文件比对对应V3交付；源码或测试变化后不能沿用旧凭据。GUI没有点击“验证”，使用IDE内置CLI执行。

## 重点边界复现

- 换向时只看新方向会漏掉尚未消退的前向速度，真实控制器测试先断言失败，补入旧目标/测得方向检查后通过。
- 采样期间时钟前进5ms，反馈/心跳可晚于周期起点；原无符号差会误判超时。真实控制器测试先失败，半周期时间比较修复后通过，并保留millis回绕测试。
- Stop标志已取走但motorStop尚未执行时，配置窗口仍须拒绝；共享仲裁及撤输出标志覆盖此窗口。
- 最终PWM饱和测试执行10000周期，覆盖前馈与trim后的真实可用区间；驱动层拒绝换向输出时清理积分。
- 旁观者的失焦、隐藏、切页和离页不自动发Stop；驾驶者待受理或运行中的动作仍会停止。重连后旧socket、旧异步响应与旧pointer释放不能停止新会话动作，手动停止/急停保持可用。

这些为确定性主机执行与显式交错注入，硬件、RTOS、NVS、ADC/I²C使用替身。它们验证真实软件模块，不能证明物理行为、多核抢占或最坏时延。

## 凭据和交付完整性

`combatbot/test-artifacts/release-evidence.json`将所有成功检查、完整日志SHA256与当前源码/测试SHA256绑定。源码改变、日志被替换或检查未成功时拒绝打包。已实际验证在完整凭据缺失时不能生成最终ZIP。

交付包附双版本编译日志、全部回归日志和凭据；打包后由verify_delivery.py检查ZIP CRC、模块哈希、维护源哈希、依赖内层ZIP CRC/版本、导出一致性及gzip还原网页。三个库为ArduinoJson7.3.1、ESP32Async/AsyncTCP3.3.2、ESP32Async/ESPAsyncWebServer3.6.0。

V2历史资料保留在docs/archive/v2.0，历史源码保留在Git基线提交；V3按本次新凭据发布。实际原生编译输入的19个CPP/H与Arduino草图逐字节一致（去除CLI注入的行号元数据）；草图入口去除CLI生成的函数声明、行号元数据和末尾空行后，也与交付ino一致。第三方离线QR脚本与基础版逐字节一致。两份新手SVG为说明图，已做XML结构检查，不是实机/IDE截图。

## 未执行的装机验收

- 实际手机视觉布局、触摸、多客户端并发及弱网行为；网页测试为Node/DOM替身。
- 网页对控制权的判断依赖最近遥测，尚未收到接管变化时存在短窗口；离页消息不保证送达，最终失联停止由固件心跳兜底。
- AP/STA与mDNS跨终端可达性、掉线重试、真实端到端响应和停车时延。
- GPIO/电平/FG物理极性和PPR、ADC与IR曲线、供电抗干扰及舵机机械限位。
- 实际多核调度、I²C阻塞、Flash写入耗时、NVS断电恢复。
- 100cm、90°、360°精度，以及低压/边缘/倾倒/堵转的真实动作。

现有接口只能撤PWM，不能保证主动刹车或车体100ms静止。会话凭据不是用户身份认证；保护默认值与IR无效策略见融合说明。软件检查通过不等于实车或量产验收。

## 复现

在combatbot目录、已有工具链和指定依赖时运行：

```powershell
python scripts/verify_release.py --pio "已有platformio.exe路径" --compiler "已有g++.exe路径" --node "已有node.exe路径"
python ../tools/package_history.py
python scripts/verify_delivery.py
```

默认原生验证使用clean；仅复核当前构建的模块改动时可显式加`--native-incremental`。该选项不跳过源码同步、模块测试或链接检查。
