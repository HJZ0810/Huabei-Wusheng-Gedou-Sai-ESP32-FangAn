## 1. 系统架构

```
┌────────────────────────── 手机 / PC 浏览器 ──────────────────────────┐
│  深色科技风 SPA：连续控制 / 精准控制 / 传感器 / 设置 四个 Tab          │
│  通信：WebSocket(实时控制+遥测 10~20Hz) + REST(配置/标定/动作)        │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  WiFi  (AP 192.168.4.1 常驻 / STA 可选)
                                │  http://combatbot.local  (mDNS + Captive Portal)
┌───────────────────────────────▼──────────────────────────────────────┐
│                        ESP32-S3  (FreeRTOS 双核)                      │
│                                                                       │
│  Core0 (网络/Web)                    Core1 (实时运动控制 1kHz)         │
│  ┌───────────────────────┐          ┌───────────────────────────────┐│
│  │ wifi_mgr  AP/STA状态机│          │ 位置环 → 速度环 → 航向环 PID   ││
│  │ mDNS / DNSServer      │   Queue  │ 梯形速度规划                   ││
│  │ ESPAsyncWebServer     │◄────────►│ FG 带符号计数 (PCNT)           ││
│  │ WebSocket / REST      │          │ IMU 零偏补偿 + 互补滤波        ││
│  │ NVS 配置持久化        │          │ 安全看门狗(心跳/堵转/低压)     ││
│  └───────────────────────┘          └───────────────┬───────────────┘│
│                                                      │                │
│  ┌───────────────────────────────────────────────────▼───────────────┐│
│  │ 传感器采集任务 (20Hz)                                              ││
│  │ CD74HC4067→ADC1(红外×6+电池) │ MCP23017(灰度×4+E18×3) │ I²C IMU   ││
│  └───────────────────────────────────────────────────────────────────┘│
└───────┬───────────────┬────────────────┬────────────────┬─────────────┘
        │ LEDC PWM×5    │ DIR GPIO×4     │ FG 输入×4      │ I²C
┌───────▼───────────────▼────────────────▼────────────────▼─────────────┐
│ 双向电平转换(3.3V↔5V) → 4×JGB37-3625  │  MPU6050 / ADXL345 / MCP23017  │
│                                        │  15kg 舵机                     │
└────────────────────────────────────────┴──────────────────────────────┘
                    24V 12A 锂电 → DC-DC 5V/5A → 3.3V LDO
```

**为什么双核分工**：WiFi 协议栈与 WebSocket 会抢占 CPU，若与 1kHz 电机控制环同核，会出现速度环抖动、FG 计数丢脉冲。Core1 跑硬实时控制，Core0 跑网络，通过队列/互斥共享状态。

## 2. 硬件层设计

### 2.1 电源树（重要，做不好会反复重启）

```
24V 锂电池（满电 ~25.2V / 亏电 ~21V）
   ├── 直接供 4× JGB37-3625 电机（大电流，峰值可达 4~8A）
   ├── DC-DC 降压模块 24V→5V   ≥5A   → 舵机(峰值1~2A) + 传感器(5V) + ESP32 的 5V/VIN
   └── （可选第二路）24V→5V 隔离小电流 → 仅给 ESP32，避免舵机动作拉垮主控
                                          ↓
                                   ESP32 板载 LDO → 3.3V
```

- **必须共地**：电机驱动地、DC-DC 地、ESP32 地单点汇接（星型接地），避免地弹。
- **去耦**：电机电源端并 470µF 电解 + 0.1µF 陶瓷；ESP32 的 5V 入口并 220µF。
- **电池电压检测**：100kΩ + 10kΩ 分压（24V → 2.18V），接入 CD74HC4067 的 CH6，不额外占用 MCU 引脚。

### 2.2 电机接口（四线制，逐个确认）

| 线色 | 含义 | ESP32 侧 | 处理 |
|---|---|---|---|
| 红 / 黑 | 24V 电源 ± | 不接 MCU | 直接从电池取电 |
| 白 | 方向：悬空/高=CCW，接低(≤0.6V)=CW | 普通 GPIO 推挽输出 | 经电平转换器 → 5V |
| 蓝 | 调速：0~5V 模拟电压 | LEDC PWM 20kHz / 10bit | 电平转换器 → 5V，再 RC 低通(1kΩ+0.1µF)平滑成直流 |
| 黄 | FG 测速脉冲（5V 方波） | PCNT / 中断输入 | **必须分压到 3.3V**（1kΩ+2kΩ）或经电平转换器 |

**关于 PWM vs 真模拟**：蓝线规格是"0~5V 模拟电压调速"。最稳妥做法是 PWM 经 RC 滤波变成直流；若电机内部已有滤波，也可直接灌 5V PWM。建议两种都留：网页设置里提供"调速信号模式：PWM直驱 / RC滤波"开关，实测哪种平滑用哪种。

**关于 FG 脉冲数**：规格书标称"转一圈输出 9 个方波脉冲"，但未说明是电机轴还是输出轴，且不同批次可能不同。**因此本方案不依赖该理论值**——直接走"行程标定"，实测出「脉冲数/厘米」，PPR 仅作参考默认（默认 90 = 9 × 减速比 10）。

### 2.3 引脚分配表

| 功能 | GPIO | 备注 |
|---|---|---|
| CD74HC4067 SIG | GPIO4 | ADC1_CH3（**必须用 ADC1**） |
| CD74HC4067 S0/S1/S2/S3 | GPIO5 / 6 / 7 / 8 | 地址选择 |
| I²C SDA / SCL | GPIO9 / GPIO10 | MPU6050(0x68) + ADXL345(0x53) + MCP23017(0x20) |
| 舵机 PWM | GPIO11 | LEDC，50Hz |
| M1 左前 DIR / PWM / FG | GPIO12 / 13 / 14 | |
| M2 右前 DIR / PWM / FG | GPIO15 / 16 / 17 | |
| M3 左后 DIR / PWM / FG | GPIO18 / 21 / 38 | |
| M4 右后 DIR / PWM / FG | GPIO39 / 40 / 41 | |
| 备用 | GPIO1 / 2 / 42 / 43 / 44 / 47 / 48 | GPIO1/2 也是 ADC1，可作模拟备用 |

**已避开的引脚**：GPIO0/3/45/46（strapping）、GPIO19/20（USB D-/D+）、GPIO26~32（Flash/PSRAM，模块未引出）、GPIO33~37（Octal PSRAM，N16R8 占用）。

MCP23017 端口：GPA0~3 = 灰度 1~4；GPA4~6 = E18 1~3。
CD74HC4067 通道：CH0~5 = 红外测距 1~6；CH6 = 电池分压；CH7~15 预留。

## 3. 运动学与控制算法

### 3.1 符号定义

| 符号 | 含义 | 默认 | 单位 |
|---|---|---|---|
| D | 轮直径 | **72.0**（模型核实） | mm |
| C | 轮周长 = π·D | ≈226.19 | mm |
| T | 轮距（左右轮中心距） | **170**（实测） | mm |
| L | 轴距（前后轮中心距） | **154**（实测） | mm |
| PPR | 每转 FG 脉冲数 | 90（**走标定**） | 个/圈 |
| K_odo | 脉冲数 / 厘米（标定实测） | — | 个/cm |
| K_turn | 转向打滑修正系数（标定实测） | 1.00 | — |

### 3.2 直线行走

- 目标距离 s(cm) → 目标脉冲数：`N = s × K_odo`
- 实际里程：`dist = Δpulse / K_odo`
- 左右轮速差修正：`pwm_L += Kp_straight × (pulse_R - pulse_L)`（防止因电机个体差异跑偏）

### 3.3 原地转向（同坦克转向，左右轮等速，反向）

- 转角 θ（弧度）→ 单侧轮行程：`s = θ × T / 2`
- 目标脉冲数：`N = θ × T × K_odo / 2`  →  代入标定系数后：`N = θ(度) × π/180 × T × K_turn × K_odo / 2`
- 转 90° 示例（T=170mm）：`s = 1.5708 × 170 / 2 = 133.5mm`（0.59 轮圈）；转 360° 单侧 534.1mm（2.36 圈）
- **轴距 L 不进入此公式**，但 L 越大转向阻力越大、打滑越多 —— 这正是 K_turn 存在的原因。

### 3.4 其他运动模式（可扩展）

- 绕单侧轮转向（一侧锁死）：外侧轮行程 `s = θ × T`
- 给定半径 R 的弧线：`v_L : v_R = (R − T/2) : (R + T/2)`；角速度 `ω = (v_R − v_L) / T`

### 3.5 梯形速度规划（禁止直接满速启停）

```
  速度
   ▲
vmax├──────────┐
   │        ↗     ↘
   │     ↗          ↘
  0└────────────────────► 时间
    加速段   匀速段  减速段
```
- 减速点由剩余距离反推：`s_brake = v² / (2·a_dec)`，当 `剩余距离 ≤ s_brake` 时切入减速段。
- 低速段设 PWM 死区（克服静摩擦的最小占空比），否则静止时 PID 输出太小转不起来。

### 3.6 三级闭环

```
         ┌──────────── 位置环 (P为主, 100Hz) ────────────┐
         │ e = N_target − N_actual  →  v_target          │
         └───────────────────┬───────────────────────────┘
                             ▼
         ┌──────────── 速度环 (PI, 200Hz) ───────────────┐
         │ e = v_target − v_FG   →  PWM                  │
         └───────────────────┬───────────────────────────┘
                             ▼
         ┌──────────── 航向环 (P+D, 200Hz) ──────────────┐
         │ e = θ_target − θ_fused  →  左右轮速差补偿      │
         └───────────────────────────────────────────────┘
```

### 3.7 偏航角融合（互补滤波）

- IMU 分支（高频好、有零偏漂移）：`yaw_imu += (ω_z − bias) × dt`
- 里程计分支（无漂移、打滑会跳变）：`yaw_odo += (s_R − s_L) / T`
- 融合：`yaw = α × yaw_imu + (1 − α) × yaw_odo`，**推荐 α = 0.85**（打滑严重时可调高到 0.95）
- 零偏标定：静止 3 秒采样 ω_z 求均值存入 NVS；长时间动作中若检测到静止（四轮脉冲无变化 > 1s）自动更新零偏。

### 3.8 FG 带符号计数（关键细节）

FG 是单相脉冲，没有方向。实现：
```cpp
// 方向符号由下发指令决定，计数时带符号累加
int32_t delta = (dirSign > 0) ? +1 : -1;   // 每次 FG 边沿
pulseCount += delta;
```
若不做符号处理，后退时里程会反向累积为负增长，位置环直接失控。

### 4.1 状态机

```
        ┌─────────┐  上电
        │  BOOT   │
        └────┬────┘
             ▼
      ┌──────────────┐
      │   AP_ONLY    │◄──────────────┐
```

## 6. 标定流程（三步，决定精度上限）

### 步骤 1 · IMU 零偏标定
车静止放置 → 点击「标定零偏」→ 采样 3 秒 ω_z 求均值 → 写入 NVS。
> 必须每次上电后首次使用前做一次；温度漂移大时可随时重做。

### 步骤 2 · 行程标定（解算 K_odo）
1. 在地面量出一条 **100cm** 直线并做起点/终点标记。
2. 网页输入 100 → 点「行程标定」→ 小车自动直线走完。
3. 用尺子量**实际走的距离**（比如 103.5cm），输入实测值。
4. 固件用总脉冲数 ÷ 实测距离，算出 `K_odo（脉冲/厘米）` 写入 NVS。
> 这一步直接绕开了"FG 每转到底几个脉冲"的不确定性，是最稳妥的做法。

### 步骤 3 · 转向标定（解算 K_turn）
1. 点击「转向标定」→ 小车原地转 360°（按当前 K_turn=1.00 执行）。
2. 观察实际停下时转了多少度（比如只转了 342°）→ 输入实测值。
3. `K_turn_new = 360 / 342 × K_turn_old`，写入 NVS。
4. 重复 1~3 一到两次即可收敛。
> 高摩擦驼峰轮打滑严重，这一步**不能省**，否则 90° 会变成 80° 左右。

## 7. 安全设计

| 机制 | 触发 | 动作 |
|---|---|---|
| 上电默认 | 任何启动 | PWM=0，舵机回中，禁止自启动 |
| 心跳看门狗 | >1000ms 无心跳 | 立即停车 |
| 连接断开 | WebSocket onclose / 页面关闭 / 切后台 | 立即停车 |
| 急停按钮 | 单击 | 停车 + 锁定，需再次点击解锁 |
| 低压保护 | 电池 < 阈值（默认 21.5V） | 告警 + 限速 50% |
| 堵转保护 | PWM 高但 FG 无脉冲 > 1.5s | 停机 + 告警 |
| 舵机限位 | 超出设定行程 | 截断输出 |
| 边缘保护（可选开关） | E18/灰度判定悬空 | 自动刹车 |

## 8. 实施路线（7 阶段，每阶段验证点）

| 阶段 | 内容 | 验证点 |

| ① 电源与接线 | 24V→5V 降压、共地、去耦、分压、电平转换；按引脚表接线 | ESP32 在电机满载启停时**不复位** |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 24V 大电流干扰导致 ESP32 复位 | 致命 | 独立 DC-DC、星型接地、470µF 去耦、必要时主控单独一路降压 |
| ADC2 与 WiFi 冲突 | 模拟量读不出 | 只用 ADC1；红外走 4067 |
| FG 无方向导致里程错误 | 精准控制失效 | 软件维护 dirSign，带符号计数 |
| 驼峰轮打滑严重 | 转角误差大 | K_turn 标定 + MPU6050 融合（α=0.85） |
| MPU6050 零偏温漂 | 长时间漂移 | 一键标定 + 静止时自动更新零偏 |
| Android mDNS 解析失败 | 打不开页面 | IP 直显 + 二维码 + captive portal 三重兜底 |
| FG 每转脉冲数未知 | 换算错误 | 不依赖理论值，走行程标定 |
| LEDC 通道不够（8 路） | 舵机/电机冲突 | 4 电机 + 1 舵机 = 5 路，留 3 路余量 |
| 蓝线调速信号 0~5V | 只能跑 2/3 速度 | 电平转换器抬到 5V + RC 滤波 |
